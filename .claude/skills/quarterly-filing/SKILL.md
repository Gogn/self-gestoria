# Расчёт квартальных деклараций

## Предусловия

Нужны `my-data/profile.yaml` и `my-data/<ГОД>-Q<N>/data.yaml`.
Чего-то нет → сначала `/collect-data` (а если есть прошлые декларации —
`/import-history`). Не считай на неполных данных.

Если в профиле есть поля `source: unknown`, влияющие на расчёт (тип клиента, режим) —
скажи об этом до выдачи цифр, а не после.

🔴 **Гейт по режиму — до любой арифметики.** Проверь `profile.residence`:

- `special_tax_regime_93: true` → особый режим art. 93 LIRPF. Обычная схема
  **неприменима**, этот репозиторий профиль не покрывает. Не считай, скажи прямо,
  направь к gestor.
- `status: non_resident` → другой налог (IRNR), другие модели. То же.
- `residence_source: unknown` → спроси (вопрос 0 в `knowledge/00-profile-decision-tree.md`)
  прежде чем считать. Так же, как с режимом IRPF и типом клиента.

## Шаг 1. Прочитай профиль и определи логику НДС

Из `my-data/profile.yaml` → `clients`. Сопоставь с `knowledge/00-profile-decision-tree.md`,
вопрос 2, и **явно проговори пользователю**, какая логика НДС применяется:

| Клиенты | Логика |
|---|---|
Вне ЕС, юрлицо | НДС не начисляется (*no sujeto* по правилам локализации), оборот в справочную графу, вычет входящего НДС сохраняется |
Испания | НДС начисляется, заполняется блок IVA devengado |
ЕС, юрлицо | НДС не начисляется (*inversión del sujeto pasivo*), нужна модель 349 |
Физлица вне Испании | ⚠️ Зависит от типа услуги. Остановись и скажи, что нужна консультация |

Смешанные клиенты → каждый тип обрабатывается отдельно. Не усредняй.

## Шаг 2. Считай на калькуляторе

**Всю арифметику — через Bash/python, никогда в голове.** Округление до 2 знаков.

```bash
python3 -c "
income_q   = 0.00   # доход за квартал
income_ytd = 0.00   # доход с 1 января
exp_ytd    = 0.00   # расходы с 1 января (все деловые)
prev_c07   = 0.00   # Σ ПОЛОЖИТЕЛЬНЫХ casillas 07 поданных 130 прошлых кварталов года
                    #   (не 19 и не «уплачено»: неоплаченный 130 тоже входит)
prev_c16   = 0.00   # Σ casillas 16 тех же 130
reten      = 0.00   # retenciones с 1 января
c13_in     = 0.00   # minoración art. 110.3.c, если положена
neg19_in   = 0.00   # невычтенные отрицательные 19 прошлых кварталов года, без знака
c16_in     = 0.00   # вычет по ипотеке, если есть право
c18        = 0.00   # только для complementaria: результат ранее поданной 130 за период
vat_base   = 0.00   # база расходов с испанским НДС за квартал
vat_cuota  = 0.00   # входящий НДС за квартал
vat_credit = 0.00   # накопленный кредит из прошлых периодов

neto = round(income_ytd - exp_ytd, 2)
c04  = round(neto * 0.20, 2) if neto > 0 else 0.00
c05  = round(prev_c07 - prev_c16, 2)
c07  = round(c04 - c05 - reten, 2)
# Раздел III — по Instrucciones, разметка в knowledge/modelo-130-irpf.md
c12  = max(c07, 0.00)                                   # раздел II пуст
c14  = round(c12 - c13_in, 2)
c15  = round(min(neg19_in, c14), 2) if c14 > 0 else 0.00
c16  = round(min(c16_in, c14 - c15), 2) if c14 > 0 else 0.00   # 15 + 16 не больше 14
c17  = round(c14 - c15 - c16, 2)
c19  = round(c17 - c18, 2)
print(f'130: 01={income_ytd:.2f} 02={exp_ytd:.2f} 03={neto:.2f} 04={c04:.2f} 05={c05:.2f} 06={reten:.2f} 07={c07:.2f}')
print(f'130: 12={c12:.2f} 13={c13_in:.2f} 14={c14:.2f} 15={c15:.2f} 16={c16:.2f} 17={c17:.2f} 18={c18:.2f} 19={c19:.2f}')

c45  = round(vat_cuota, 2)
c46  = round(-c45, 2)
# 66 == 46 при 65 = 100 % и пустых 58 / 76 (см. «Блок итога» в knowledge/modelo-303-iva.md)
c66  = c46
print(f'303: 28={vat_base:.2f} 29={vat_cuota:.2f} 45={c45:.2f} 46={c46:.2f} 66={c66:.2f} 110={vat_credit:.2f} oborot={income_q:.2f}')

# Итог — НЕ 46 − 110. Кредит идёт через 78 (зачтено) и 87 (остаток дальше).
if vat_credit > 0 and c66 > 0:
    print('СТОП: 66 > 0 при накопленном кредите. Сколько кредита зачесть в 78, в knowledge/ не размечено —')
    print('      сверить в Instrucciones 303 / PRE303, не считать самому. 87 = 110 − 78.')
else:
    c78 = 0.00                      # зачитывать нечего: результат ≤ 0 или кредита нет
    c87 = round(vat_credit - c78, 2)
    c71 = round(c66 - c78, 2)       # 71 == 66 при 78 = 0 — разбор в examples/perfil-a-cliente-no-ue.md
    if c45 == 0 and income_q == 0:
        kind = 'sin actividad'
    else:
        kind = 'a ingresar' if c71 > 0 else 'resultado cero' if c71 == 0 else 'a compensar (или solicitud de devolución)'
    print(f'303: 78={c78:.2f} 87={c87:.2f} 71={c71:.2f} → {kind}')
"
```

Формулы и смысл casillas — `knowledge/modelo-130-irpf.md` и `knowledge/modelo-303-iva.md`.

⚠️ Формула для 303 в примере выше верна **только** при пустом IVA devengado.
Если клиентам НДС начисляется, считай `46 = devengado − deducible`.

🔴 **Итог 303 — не `46 − 110`.** Накопленный кредит не вычитается из результата
напрямую: в 110 он стоит целиком, в 78 — сколько зачтено в этом периоде, в 87 —
остаток на следующий. При отрицательном результате `78 = 0`, `87 = 110`, а итог 71
равен результату квартала. Пустая 87 при существующем кредите — кредит потерян.

## Шаг 3. Обязательные проверки

Запусти `/consistency-check`. Ни один расчёт не выдаётся пользователю без сверки.

Минимум:
- доход в 130 согласуется с оборотом в 303;
- расходы в 130 ≥ базы расходов в 303;
- casilla 05 не пустая, если это не Q1;
- casilla 110 перенесена, если кредит был.

Нашёл расхождение → **не выдавай цифры**. Сначала объясни расхождение и найди причину.

## Шаг 4. Выдай расчётный лист

Заполни `templates/worksheet.example.md` и сохрани в
`my-data/<ГОД>-Q<N>/worksheet.md`. В нём должно быть:

1. Исходные данные, из которых считалось.
2. Таблица «casilla → значение» для 303.
3. Таблица «casilla → значение» для 130.
4. Итог: сколько платить и какой результат по НДС.
5. Величины, которые понадобятся в следующем квартале.
6. Дисклеймер.

В ответе пользователю дай **обе таблицы casillas** — это то, ради чего он пришёл.
Числа приводи в испанском формате (запятая как десятичный разделитель), потому что
вбивать он будет именно так.

## Шаг 5. Инструкции по подаче

- Срок и сколько дней осталось (`knowledge/deadlines.md`). Проверь правило переноса
  с выходных — не называй «20-е число» не глядя в календарь.
- 🔴 Срок сверяй по официальному календарю AEAT, а не по таблице в `knowledge/deadlines.md`
  (она вторична и может отстать): https://sede.agenciatributaria.gob.es/Sede/en_gb/calendario-contribuyente.html
- Если напоминания не настроены — предложи подписку на **официальный iCalendar** AEAT,
  дополнительно [radarfiscal.es](https://radarfiscal.es) или
  [@Autonomo_Help_Bot](https://t.me/Autonomo_Help_Bot) как страховку на следующий квартал.
- 👉 **Рекомендуй прямую оплату 130 (NRC / картой)**, а не домициляцию, со ссылкой на
  `knowledge/pitfalls.md` §1 — объясни в одну фразу, чем это кончилось в реальном кейсе.
- Совет прогнать 303 через **PRE303** и сверить нумерацию casillas.
  👉 Если в `my-data/profile.yaml` заполнен блок `calibration` (номер справочной графы оборота
  из ранее поданной декларации) — используй **его**, а не свою догадку, и скажи
  пользователю, из какого периода этот номер взят.
- Скачать *justificante* обеих деклараций в `my-data/<ГОД>-Q<N>/`.
- Если в профиле есть активная рассрочка — напомни про её ближайший платёж и что
  платить надо через *Aplazamientos → Contestar requerimientos y otras gestiones*,
  а не обычной кнопкой оплаты.

## Обязательный дисклеймер

Каждый итоговый расчёт заканчивается тем, что это не профессиональная налоговая
консультация, номера casillas нужно сверить в актуальной форме, а ответственность за
содержание декларации несёт налогоплательщик.
