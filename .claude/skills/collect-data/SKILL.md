# Сбор данных для подачи

## Шаг 1. Профиль

Проверь `my-data/profile.yaml`.

**Если файла нет** — сначала спроси: **подавались ли декларации раньше** (самим
пользователем или гестором)?

- **Да** → 👉 не проходи вопросник. Запусти `/import-history`: профиль восстановится из
  justificantes надёжнее, и только оттуда берутся переносимые величины. Вернёшься сюда
  за данными текущего квартала.
- **Нет, первая подача** → пройди `knowledge/00-profile-decision-tree.md`, вопрос за
  вопросом, по одному за раз. Не задавай все семь сразу.

Заполняя профиль по ответам, помечай поля `source: asked` — чтобы позже было видно, что
это не подтверждено декларацией.

Особое внимание:
- Вопрос 2 (страна и тип клиентов) определяет всю логику НДС. Не идти дальше, пока не ясно.
- Вопрос 6 (активы за границей) — спросить обязательно, даже если пользователь не
  поднимал тему. Штрафы по модели 720 высокие.
- Вопрос 7 — если клиенты испанские, проверить, не освобождён ли он от 130 вовсе.

Результат запиши в `my-data/profile.yaml` по образцу `templates/profile.example.yaml`.
Выведи пользователю итоговый набор моделей и объясни, **почему** именно эти.

**Если файл есть** — прочитай, кратко подтверди профиль одной фразой, спроси, не
изменилось ли что-то (новые клиенты, сотрудники, аренда), и иди к шагу 2.

## Шаг 2. Определи период

Сегодняшняя дата → какой квартал подаём. Сверься с `knowledge/deadlines.md`.

Сразу скажи пользователю:
- срок подачи и сколько дней осталось;
- если он выбирает домициляцию — что дедлайн для него на несколько дней раньше;
- если срок уже прошёл — не пугай, но объясни: подать с опозданием намного дешевле,
  чем не подать (`knowledge/pitfalls.md` §9);
- ⚠️ проверь правило переноса: срок на выходном сдвигается на следующий рабочий день
  (например, Q4 2026 → не 30.01.2027, а 01.02.2027).

Сроки сверяй по **официальному календарю AEAT** — это первоисточник:
https://sede.agenciatributaria.gob.es/Sede/en_gb/calendario-contribuyente.html

Если пользователь ещё не настроил напоминания — предложи один раз (не навязывай повторно):
подписка на **официальный iCalendar** AEAT, а дополнительно
[radarfiscal.es](https://radarfiscal.es) (фильтрует под профиль, есть русская версия) или
бот [@Autonomo_Help_Bot](https://t.me/Autonomo_Help_Bot). Оговори, что сторонние сервисы —
второй контур и **не** замена *Mis notificaciones*: личные требования от Hacienda видны
только там.

## Шаг 3. Собери данные за квартал

Вопросник — `templates/data-request.md`, часть 2. Форма — `templates/quarter.example.yaml`.

Порядок и правила:

1. **Доходы.** По каждому счёту: дата, номер, база, НДС, страна и тип клиента.
   👉 Напомни: учитывается **дата счёта, а не дата оплаты**.

2. **Расходы.** По каждому — два независимых вопроса:
   - есть ли **испанский НДС** и полная *factura* → попадает в 303 (casillas 28/29);
   - является ли **деловым расходом** → попадает в 130 (casilla 02).
   Расход может быть деловым без НДС — тогда только в 130.

3. **Cuota de autónomos — спроси отдельным вопросом.** Это самый забываемый расход.
   Не принимай «наверное учтено» — нужна сумма за квартал.

4. **Пройди по `knowledge/gastos-deducibles.md`** и спроси про типовые пропуски:
   софт и подписки, хостинг и домены, профессиональные услуги, банковское
   обслуживание, обучение, страховки, работа из дома (если заявлено в 036).
   Не навязывай сомнительные вычеты — три условия вычитаемости должны выполняться.

5. **Накопительные величины.** 🔴 Никогда не принимай их по памяти.
   - Если история импортирована → бери из `my-data/history/summary.md`, блок
     «переносимые величины».
   - Если нет → направь пользователя скачать justificantes предыдущих деклараций
     (*Consultar declaraciones presentadas*) и предложи `/import-history` — это быстрее,
     чем выписывать casillas вручную.
   - Для Q1 всё, кроме НДС-кредита, — нули (кредит живёт между годами).

Результат — `my-data/<ГОД>-Q<N>/data.yaml`.

## Шаг 4. Проверь полноту

Перед тем как считать, убедись, что есть всё:

- [ ] хотя бы одна запись дохода ИЛИ явное подтверждение «дохода не было»
- [ ] cuota de autónomos указана явно (или явно «не платил, потому что...»)
- [ ] у каждого расхода заполнены `has_spanish_vat` и `deductible_irpf`
- [ ] накопительные величины заполнены (нули для Q1 — это заполнено)
- [ ] НДС-кредит из предыдущей 303 перенесён

Чего не хватает — спроси. Не подставляй значения по умолчанию за пользователя и не
угадывай суммы.

## Шаг 5. Передай дальше

Скажи, что данные собраны, и предложи запустить расчёт: `/quarterly-filing`.

## Дисклеймер

Если по ходу сбора данных объясняешь налоговые правила — оговаривай, что это не
профессиональная налоговая консультация, а спорные вопросы (тип клиента, вычитаемость
конкретного расхода) стоит подтвердить у gestor или в AEAT.

## Запрещено

- Просить NIF, ФИО, IBAN, адрес, пароли, PIN, коды Cl@ve. Для расчёта они не нужны.
- Записывать что-либо из перечисленного в файлы вне `my-data/`.
- Придумывать суммы, если пользователь не смог их найти.
