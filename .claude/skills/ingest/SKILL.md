# Ingest — новый источник в базу

Операция *ingest* из паттерна LLM-Wiki: источник один раз читается, а знание из него
расходится по всем страницам, которых оно касается, — а не остаётся в разговоре.

Один источник за раз. Пользователь видит, что меняется, и коммитит сам.

## Вариант: вывод из разговора (*query*)

Источника-документа нет, но в разговоре получен вывод, который переживёт разговор:
сверка, расчёт, разобранный вопрос. Шаги 0–2 пропускаются, дальше — с шага 3. В журнале
операция `query`. Когда записывать, а когда нет — правило в `CLAUDE.md`
(«Вывод из разговора возвращается в базу»).

👉 Открытый вопрос, записанный в `knowledge/`, всегда проверять на профиль: если он
касается текущего квартала, он идёт и в `my-data/<ГОД>-Q<N>/open-issues.md`.

## Шаг 0. Публичный или личный

| Источник | Оригинал | Знание |
|---|---|---|
| Норма: BOE, Orden, RD | `sources/` через `sources/fetch.py` | `knowledge/` |
| Инструкции и страницы AEAT | `sources/aeat/` через `sources/fetch.py` | `knowledge/` |
| Justificante, notificación, datos fiscales, выписка | `my-data/` (`history/`, `ingresos/`, `gastos/`) | `my-data/` |
| Письмо гестора, форум, пересказ | `my-data/` | 🔴 в `knowledge/` — только после подтверждения первоисточником |

🔴 Личное в публичные папки не попадает: ни идентификаторы, ни реальные суммы. Общий
вывод из личного документа идёт в `knowledge/` обезличенным и с условными цифрами.

## Шаг 1. Сохранить оригинал

- **BOE / AEAT** — запись в `sources/manifest.json` и
  `python3 -I sources/fetch.py <файл>`. Как найти блок статьи — `sources/README.md`.
  🔴 Текст в `sources/` вручную не набирать и не править: lint проверяет хеш.
- Источник, который скрипт не берёт (PDF приказа, сканы), — ссылка в
  `knowledge/sources-primarias.md` с пометкой, что дословной выдержки нет.
- **Личный документ** — файл в `my-data/inbox/`, затем в своё место по структуре
  `my-data/README.md`.

## Шаг 2. Прочитать и обсудить

Коротко изложи пользователю 3–5 главных выводов с уровнем: `[норма]`,
`[официальное разъяснение]`, `[практика]`. Спроси, что важно для него, прежде чем
править. Если источник противоречит тому, что уже записано, — скажи об этом первым.

## Шаг 3. Найти все затронутые страницы

До правок — список. Искать по статье, номеру casilla, термину и **по старой
формулировке**, которую источник опровергает:

```bash
grep -rn "<статья|casilla|термин>" knowledge templates examples .claude/skills CLAUDE.md
```

Для личного: `my-data/profile.yaml` (поле + `source:`), `open-issues.md` текущего
квартала, `debts.md`, `inmovilizado.md`, `data.yaml` квартала.

👉 Типовой промах: правка в `knowledge/` не доходит до python-кода в skill, примеров и
шаблонов. Их проверять обязательно.

## Шаг 4. Обновить

- `[норма]` — только если текст есть в `sources/` или по ссылке из `sources-primarias.md`.
  Указывай статью и файл выдержки.
- Неверное прежнее утверждение исправляется **везде**, где нашлось на шаге 3.
- Противоречие, которое не решается текстом источника, не затирать: оставить оба
  варианта с `[не подтверждено]` и вынести вопрос пользователю (`open-issues.md` для
  личного).
- `Актуально на` поднимать только у страниц, содержание которых реально сверено.
- Новый якорь — в `knowledge/sources-primarias.md`.

## Шаг 5. Проверить

```bash
python3 .claude/skills/lint-knowledge/lint.py
```

🔴 не остаётся. Новые 🟡 — разобрать или объяснить.

## Шаг 6. Записать в журнал

Публичное — в `log.md` в корне, личное — в `my-data/log.md`. Только дописывать в конец:

```
## [ГГГГ-ММ-ДД] ingest | <что за источник>
- оригинал: <файл в sources/ или my-data/>
- изменено: <страницы>
- открыто: <что не решено, если есть>
```

## Шаг 7. Отчёт

Что изменилось, что осталось открытым, `git status` и сообщение коммита на английском.
Коммитит пользователь.
