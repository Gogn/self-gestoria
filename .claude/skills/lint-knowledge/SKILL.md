# Lint базы знаний

`/consistency-check` проверяет декларации. Этот skill проверяет то, по чему они
считаются: если в `knowledge/` или в skill лежит неверная формула, ошибка
воспроизведётся в каждом квартале.

Идея — операция *lint* из паттерна LLM-Wiki (A. Karpathy): периодически искать
противоречия, устаревшие утверждения, страницы без входящих ссылок и пробелы.

🔴 **Skill только находит. Ничего не исправляет без согласия пользователя.** Он сам
решает, что и как править, и сам коммитит.

## Шаг 1. Механические проверки — скрипт

```bash
python3 .claude/skills/lint-knowledge/lint.py
```

Скрипт смотрит только файлы, которые попадают в git (`my-data/` не трогает).

| Уровень | Проверка |
|---|---|
| 🔴 | Нет `> Актуально на: ГГГГ-ММ` в шапке файла `knowledge/`, или дата в будущем |
| 🔴 | Битая ссылка на файл, на `#якорь`, на название раздела в ёлочках |
| 🔴 | Неизвестный тег достоверности (в т.ч. с латинской буквой внутри) |
| 🔴 | Похожее на DNI / NIE / IBAN / e-mail / 13-значный номер в публичном файле |
| 🔴 | Сумма из текстовых файлов `my-data/` (от 100 €, с копейками) в публичном файле. Работает только локально: без `my-data/` выдаёт 🟡 «пропущено» |
| 🔴 | Файл `knowledge/` не внесён в карту в `CLAUDE.md`, или карта ссылается на несуществующий |
| 🔴 | `sources/`: нет шапки, хеш текста не сходится (файл правили вручную), рассинхрон с `manifest.json` |
| 🟡 | `Актуально на` старше 6 месяцев (`--stale-months N`) |
| 🟡 | `sources/`: на выдержку никто не ссылается |
| 🟡 | `log.md`, `my-data/log.md`: заголовок не по формату или запись не в хронологическом порядке |
| 🟡 | Нет `> Перепроверять:` в шапке |
| 🟡 | Много номеров casillas, а год формы в шапке не указан |
| 🟡 | `[норма]` без статьи или акта в соседних строках |
| 🟡 | На файл не ссылается ничего, кроме `CLAUDE.md` |
| 🟡 | Skill не упомянут в `README.md` |
| 🟢 | Инвентарь: числа, повторяющиеся в разных файлах; строки со ставками и прошлым годом; акты без якоря в `sources-primarias.md` |

Ложное срабатывание → поправь скрипт, а не обходи находку молча.

⚠️ Сверка сумм видит только то, что есть **текстом** в `my-data/` (`.md`, `.yaml`,
`.txt`): цифры, которые лежат лишь в PDF, она не найдёт. Круглые суммы (`,00`) и
меньше `--min-amount` пропускаются. Поэтому в примерах и шаблонах всё равно держи
**условные** суммы, а не «настоящие, но без имени».

## Шаг 2. Смысловые проверки — сам агент

Скрипт не понимает смысла. Дальше — чтение.

### 2.1. Повторяющиеся факты 🔴

Возьми инвентарь 🟢 и открой каждое место. Один и тот же факт должен:
- иметь одно значение;
- иметь один уровень уверенности. Если в одном файле «порядка 2 000 €, уточнить», а в
  другом «макс. 2 000 €» без оговорки — это расхождение;
- нести одинаковый тег, если тег есть.

Расхождение → предложи, какой файл считать источником, а остальные перевести на ссылку.

### 2.2. Skills и шаблоны против knowledge/ 🔴

Это главная проверка. Правка формулы в `knowledge/` часто не доходит до кода в skill.

- Формулы в `.claude/skills/*/SKILL.md` (особенно python-блоки в `quarterly-filing`)
  сравни с таблицами casillas в `knowledge/modelo-130-irpf.md` и `knowledge/modelo-303-iva.md`.
- Проверки в `consistency-check` — с теми же таблицами.
- `templates/worksheet.example.md`, `templates/filing-checklist.md`,
  `examples/*.md` — с ними же.
- Определения одной величины разными словами («уплачено» против «задекларировано»,
  «за квартал» против «с 1 января») — тоже расхождение.

### 2.3. Исправления, которые не разошлись по базе 🟡

```bash
git log --format='%h %s' -- knowledge/ | grep -iE 'fix|correct|wrong'
```

Для каждого такого коммита: что было неверно → `git show <hash>` → ищи старую
формулировку в остальных файлах (`grep`). Она могла остаться в skill, примере или
соседнем файле.

### 2.4. Уровень утверждений 🟡

- `[норма]` опирается на акт из `sources-primarias.md`. Акт из инвентаря 🟢, на котором
  стоит утверждение, а не упоминание мимоходом → добавить якорь или понизить тег.
- Категоричные утверждения о сроках, ставках, обязанностях без тега в ключевых файлах
  (`modelo-*.md`, `deadlines.md`, `pitfalls.md`) — выборочно, 5–10 мест.
- `[практика]`, поднятое до `[норма]` без новой ссылки, — ошибка.

### 2.5. Пробелы 🟢

- Понятие, которое упоминается в 5+ файлах, но не имеет своего раздела (`grep -l`).
- Вопросы, которые уже всплывали в `my-data/*/open-issues.md` и решаются общим
  правилом, но в `knowledge/` его нет. Содержимое `my-data/` в отчёт не переносить.

Пробелы, которые закрываются поиском в сети, только перечисли. Искать — по запросу.

## Шаг 3. Отчёт

```
LINT БАЗЫ ЗНАНИЙ · <дата>

🔴 Ошибки
  - <файл:строка> — что не так → что предлагается

🟡 Проверить
  - ...

🟢 Пробелы и предложения
  - ...

Скрипт: 🔴 N · 🟡 M. Смысловые: 🔴 K · 🟡 L.
```

Для каждой находки — место, суть и предлагаемая правка. Сомнительное помечай
`[не подтверждено]` и пиши, где проверить (Instrucciones AEAT, BOE), а не утверждай по
памяти.

## Правила

- **Не поднимай `Актуально на` при исправлении** ссылки или опечатки. Дата меняется
  только тогда, когда содержание файла реально сверено с источником (см. «Датированность» в
  `knowledge/sources-primarias.md`).
- **Не исправляй норму по памяти.** Если находка — «формулировка, возможно, неверна»,
  это вопрос к первоисточнику, а не правка.
- Найденное в `knowledge/` — обезличенное. Личные данные в отчёт не попадают.
- После правок прогони скрипт ещё раз и допиши в `log.md` запись `lint` — что нашлось
  и что исправлено. Прогон без правок в журнал не пишется.
- Коммит делает пользователь; предложи сообщение на английском.
